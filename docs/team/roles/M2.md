## M2-1 · Construire la capsule de décision
**Rôle :** M2 · **Quand :** Sam 13:30-17:30

**Pourquoi :** L'écran ne lit que la capsule : sans elle, M3 n'a rien à afficher.

1. Branche m2-capsule (fiche S1).
2. Crée csync/capsule.py avec une fonction build_capsule(day, states, decisions, z, reference) qui renvoie un dict conforme à contracts/decision_capsule.schema.json.
3. Ajoute tests/test_capsule.py : la capsule du jour 7 de l'histoire est valide (jsonschema) et son explication passe banned_hits().
4. python -m pytest -q, puis pull request.

**Fini quand :** tests/test_capsule.py passe ; une capsule par jour est produite.

**Prompt à coller dans Cursor :**
```text
Dans ce dépôt, lis contracts/decision_capsule.schema.json, csync/rules.py (evaluate) et csync/language.py. Crée csync/capsule.py avec build_capsule(day, states, decisions, z, reference) qui renvoie un dict conforme au schéma : 8 blocs + ui_hint (NOMINAL si CONTINUE, ACTION si OPEN_PROCEDURE CRITICAL). L'explication cite les indicateurs marqués, leur valeur, l'unité et la référence personnelle, en anglais, et ne contient aucun mot de banned_hits. human_decision vaut toujours "pending". Écris tests/test_capsule.py (valide le jour 7 de generate('histoire', seed=42, fast=True) avec jsonschema). Ne modifie pas les contrats. Lance python -m pytest -q.
```
